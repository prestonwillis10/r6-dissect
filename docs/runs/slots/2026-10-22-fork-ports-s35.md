Branch `fp/s35-reconcile-order`, base `track/fork-ports` at `95cdcab`. Test commit `da15e58`, code commit `f8f1ac493fd72ea2ccee8b5bbdafa2d5378d6de4`.
Player names: the unit tests use made-up names (`O1`, `U1`, `E1`, ...). The replay outputs below hold folder names and counts only.
Credit: the sort by player index, `TestReconcileKillsFromScoreboard_Deterministic` and the note that the `break` should be a `continue` come from closed PR #12 by @ElyasYassin.

## What changed
- `reconcileKillsFromScoreboard` (`dissect/scoreboard.go`): `overCredited` and `underCredited` are sorted by player index before the reassignment (PR #12).
- `for pass := 0; pass < 2; pass++` is now the outermost loop, so pass 0 (the kill whose `scoreboardKiller` is the under-credited player) runs over the (under, over) pairs before pass 1 (any eligible kill) runs for any pair.
- The guard in the loop over over-credited players is split: `break` when the under-credited player is satisfied, `continue` past an exhausted over-credited player.
- The guard inside the kill loop is unchanged (`if underCredited[ui].diff <= 0 || overCredited[oi].diff <= 0 { break }`): its `break` leaves only the scan of the current pair's kills, and the loop over over-credited players then moves on. Splitting it would be an equivalent change (mutant M03d below).
- New tests in `dissect/reconcile_pairs_test.go`: the plan's `TestReconcileKillsFromScoreboard_TwoPairsTimingMatched`, PR #12's `TestReconcileKillsFromScoreboard_Deterministic` (its final assertion now expects `U1>E1 U2>E2 `), and `TestReconcileKillsFromScoreboard_PairLimits` (the reviewer checklist's limits).

## Deviations from the plan
- The plan's Task 3 names one guard; the function holds the same condition at a second site, the kill loop, already at `bd6ccbe`. That site keeps its combined `break` (see What changed).
- Folded in closed PR #12 (lane decision; issue #35 listed determinism as out of scope). PR #12's final assertion `first != "U1>E1 O2>E2 "` encoded the `break` it flagged; with the guard split, the fixture's scoreboard counts (U1 and U2 gain a kill, O1 and O2 gain none) leave both kills to move, and the player-index order gives U1 the kill of O1, the lower-index over-credited player. Mutant M02 below restores the old guard and reproduces PR #12's value.
- The plan's Acceptance (15 moves against 13-14 on the corpus at `bd6ccbe`) predates #50. What the change does to the replays at `95cdcab` is in the fenced over/under histogram (Premises probed), the moves table and the byte-parity table below.
- More tests than the plan's Step 1, for the reviewer checklist's limits and PR #12's test.
- The plan's Step 4 `go test ./...` is replaced by the brief's memory-capped commands. Full -race on dissect/test: orchestrator gate.

## Mutation runs
Each mutant is applied to `dissect/scoreboard.go` in a plain export of `f8f1ac4` (`git archive`), never in the worktree, and the file is written back afterwards; the runner checks its sha256 against the export after each run.
- M00: the base function (`95cdcab`) in place of the head's, without the `sort` import.
- M01: the pass loop moved back inside the over-credited loop, around the kill loop (sorts and split guard kept).
- M02: the over-credited loop's guard back to `if underCredited[ui].diff <= 0 || overCredited[oi].diff <= 0 { break }`.
- M03a / M03b: the kill loop's guard without its over-credited / under-credited half.
- M03c: the kill loop's guard as `break overLoop`, a label on the over-credited loop (the old exit, moved to the kill loop).
- M03d: the kill loop's `break` as `continue`.
- M04a / M04b: the over-credited loop's under-credited `break` / over-credited `continue` deleted.
- M04c / M04d: that `break` as `continue` / that `continue` as `break`.
- M05 / M06: the `overCredited` / `underCredited` sort deleted.
- M07 / M07a / M07b: sorted by `r.Header.Players[...].Username` (both lists / `overCredited` / `underCredited`). M07c: both lists by descending index.
- M08: `for _, pass := range []int{1, 0}` (fallback first). M09: `pass < 1` (timing pass only). M10: `pass := 1` (fallback only).
- M11: the team check as `(false && underTeam == targetTeam) || underUsername == u.Target`.

M03d, M04a, M04b and M04c are equivalent by construction: the kill loop's guard is its first statement and tests the same condition, so a pair whose under-credited player is satisfied or whose over-credited player is exhausted moves nothing whether the over-credited loop skips it or the kill loop breaks at once. The over-credited loop's guards save the bounds lookup and the scan.
