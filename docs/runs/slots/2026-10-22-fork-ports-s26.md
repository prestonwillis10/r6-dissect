# Slot S26 (issue #26): Y10S4+ scoreboard entities map to players through the player object link

Branch `fp/s26-scoreboard-link`, base `track/fork-ports` at `7e976ae`. Code commit `70aff6dedc1b126b9bd0399d5c6f0ecea16d3eee`.
Player names: fixture names under `dissect/test/data/` are public; corpus players are `playerNN`, numbered by order of appearance in the match's R01 stats (local to this log).

## What changed
- `readScoreboardEntity` (Y10S4+ only) reads `1B <player obj> EB219B38 <entity> 18A591A1` structurally and stores entity -> owner handle.
- `ensureScoreboardMapping`: in a round with links, a linked sbID maps only through `playerIndexByObject(owner)` (lazily; unresolved stays unmapped), an unlinked one only through the `+4` rule, linked first. A round without links runs the old zip unchanged (`zipScoreboardMapping`).
- (a) `deriveTeamRoles` now moves the scoreboard state keyed by player index (`readPlayerOrder`, `scoreboardIDToPlayer`, `scoreboardFinalKills`, `lastPlayerScores`, `scoreRevives`, `lastDefuserPlayerIndex`) to the indices it leaves (`movePlayerIndices`).
- `knownMatchFailures`: the 47572 entries removed (`score-drop, #26` and the flaky `nondeterminism, #26 and PR #12`); see Corpus acceptance and 47572 determinism below.
